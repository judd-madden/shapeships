Yes — do it “per ship / per UI slice”. That’s the cleanest way to validate without inventing throwaway harnesses or hardcoded test scaffolding.

The mistake to avoid is: “finish the whole effect system first, then try to test it.” You’ll end up with a pile of unverified verbs and no confidence.

Below is how I’d structure it so each step is provable using real gameplay UI + real server state, with only minimal, permanent wiring (no temporary test pages).

Core principle: only add “plumbing” when a ship slice needs it

Even if SpendCharge is “global plumbing”, you still validate it by shipping Interceptor’s charge panel immediately after adding it — not by making a fake resolver.

So: we’ll add SpendCharge properly, but we won’t try to prove it works until a real ship uses it.
